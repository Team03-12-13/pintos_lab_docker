# Virtual Memory

메모리 가상화는 CPU 가상화보다 훨씬 복잡하며, **하드웨어(MMU)와 운영체제의 긴밀한 협력**이 필요합니다. 이를 올바르게 이해하기 위해서는 메모리 주소 구조, 보호 기법, 페이지 테이블, 스왑, 페이지 폴트 등 다양한 개념을 파악해야 합니다.

---

## 가상 주소 (Virtual Address)

운영체제는 각 프로세스에게 \*\*"자신만의 독립적인 메모리 공간을 사용하는 것처럼 보이게 하는 환상"\*\*을 제공합니다. 이로 인해 여러 프로세스가 동시에 실행되더라도 **서로의 메모리에 접근할 수 없고**, 메모리 충돌 없이 안정적으로 동작할 수 있습니다.

> 📌 가상 주소는 실제 물리 주소가 아니며, MMU와 커널이 이를 물리 주소로 변환합니다.

```c
// 예시: 가상 주소 → 물리 주소 변환 과정
가상 주소 VA = 0xB8001234
 → 페이지 번호 = 0xB8001
 → 오프셋 = 0x234
 → 페이지 테이블 통해 물리 주소 = 0x2000234
```

---

## MMU (Memory Management Unit)

CPU는 프로그램의 명령에 따라 \*\*가상 주소(VA)\*\*를 생성하여 메모리에 접근하려 합니다. 이때 **MMU**는 현재 프로세스의 **페이지 테이블**을 참조하여 해당 주소를 \*\*물리 주소(PA)\*\*로 변환합니다.

* 주소 변환은 실행 중 실시간으로 일어나며
* MMU는 TLB(TLB 미스 시 페이지 테이블)를 통해 이를 효율적으로 수행합니다.

---

## 가상 메모리의 역할과 이점

| 역할             | 설명                              |
| -------------- | ------------------------------- |
| **고립 및 보호**    | 각 프로세스의 주소 공간을 분리하여 보안과 안정성을 보장 |
| **주소 공간 확장**   | 실제 RAM보다 큰 메모리 공간을 사용할 수 있도록 지원 |
| **효율적 메모리 사용** | 사용 중인 페이지만 물리 메모리에 적재           |
| **간편한 메모리 관리** | 스택/힙/코드/데이터 영역을 유연하게 관리 가능      |

---

## 페이지 기반 메모리 관리

가상 메모리 시스템에서는 주소 공간을 **페이지(Page)** 단위로 나눕니다. 물리 메모리는 동일 크기의 \*\*프레임(Frame)\*\*으로 나뉘며, 매핑이 페이지 테이블에 저장됩니다.

* **페이지 테이블**: 가상 주소 → 물리 주소 매핑
* **TLB (Translation Lookaside Buffer)**: 주소 변환 캐시
* **페이지 폴트(Page Fault)**: 필요한 페이지가 메모리에 없을 때 발생하는 예외

---

## 페이지 폴트 처리 흐름 (Lazy Loading)
1. 프로세스가 아직 적재되지 않은 주소에 접근
2. MMU가 페이지 테이블에서 매핑 실패 → TLB 미스 → 페이지 폴트 발생
3. 커널이 디스크에서 필요한 페이지를 메모리로 로드
4. 페이지 테이블을 갱신
5. 실패했던 명령 재시도

> 📎 PintOS의 lazy loading이 이 로직을 구현하게 함

---

## 스왑(Swap) 공간
* 메모리가 부족할 경우 **사용 빈도가 낮은 페이지**를 디스크의 **스왑 영역**으로 내보냅니다.
* 필요 시 다시 물리 메모리로 적재 (Swap-in)
* 이는 대규모 다중 작업을 가능하게 함

> Swap은 디스크 접근이기 때문에 속도는 느림. 성능 병목 원인이 될 수 있음.

---

## 페이지 교체 알고리즘
페이지 폴트 시 새로운 페이지를 넣기 위해 기존 페이지를 제거해야 할 수 있습니다. 이때 어떤 페이지를 교체할지 결정하는 **알고리즘**이 필요합니다.

| 알고리즘      | 설명                                |
| --------- | --------------------------------- |
| **FIFO**  | 가장 먼저 들어온 페이지 제거 (단순하지만 성능 저하 우려) |
| **LRU**   | 가장 오랫동안 사용되지 않은 페이지 제거            |
| **Clock** | 순환 방식으로 최근 사용 여부를 참조하여 제거 결정      |

---

## TLB 미스 (TLB Miss) 핸들링
* TLB는 자주 참조되는 주소 변환 정보를 저장
* TLB에 원하는 항목이 없을 경우 → TLB 미스 발생 → 페이지 테이블 직접 접근 → 시간 소모 증가
* 운영체제는 적절한 TLB 교체 정책으로 이 문제를 완화

## PintOS의 가상 메모리 구현 (Project 3)

### 구현 내용

* 사용자 **페이지 테이블** 구성 및 보호
* **Lazy Loading** 기반 페이지 로딩 구현
* **스택 자동 확장 (Stack Growth)**
* **Swap-in / Swap-out** 구현
* **Memory-mapped file (mmap)** 구현 및 관리

### 관련 개념 추가 정리

* **Supplemental Page Table**: 사용자 프로세스의 페이지 상태 관리 (디스크/메모리 여부 등)
* **Frame Table**: 어떤 프레임이 어떤 페이지와 연결되었는지 추적
* **Eviction Policy**: LRU 기반으로 구현되는 경우 많음
* **Pinning**: 페이지를 스왑 못 하게 잠금 (예: 파일 읽기 중)

## PintOS Project 3 테스트 목록

### 기본 페이지 로딩 테스트

* `vm/pt-grow-stack`: 스택 자동 확장 테스트
* `vm/pt-write-code`: 코드 영역 쓰기 보호 테스트
* `vm/pt-grow-bad`: 잘못된 스택 확장 시도 방지 테스트
* `vm/pt-write-stack`: 스택 쓰기 정상 동작 확인

### Lazy Loading 테스트

* `vm/pt-exec-once`: 실행 파일 Lazy Load 테스트
* `vm/pt-exec-multiple`: 다중 페이지 Lazy Load 테스트

### mmap 테스트

* `vm/mmap-read`: mmap된 파일 읽기
* `vm/mmap-write`: mmap된 영역 쓰기
* `vm/mmap-close`: mmap된 파일 닫기
* `vm/mmap-remove`: unlink 후 mmap 접근
* `vm/mmap-exit`: 종료 시 mmap 해제

### Swap 관련 테스트

* `vm/page-linear`: 연속적인 페이지 접근 → 스왑 발생 확인
* `vm/page-parallel`: 여러 프로세스의 스왑 동시 접근 확인
